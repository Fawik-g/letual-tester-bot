# Тестер-бот Лэтуаль (MVP)

Telegram-бот контроля состояния тестеров в магазинах. Покупатель сканирует QR-код рядом
с тестером и отправляет жалобу — она мгновенно приходит сотрудникам **именно этого
магазина**. Сотрудники ежедневно обходит магазин и отмечают состояние тестеров.
Рассчитан на пилот из 3 магазинов.

## Роли

| Роль | Что делает |
|---|---|
| **Покупатель** | Сканирует QR у тестера → выбирает проблему (пустой, загрязнён, сломан, испорчен, нет на месте…) → опционально фото и комментарий. Задача уходит сотрудникам этого магазина; покупатель получает уведомление, когда её решат. |
| **Сотрудник** | Входит по инвайт-коду (`/staff`) или добавляется админом напрямую. Получает задачи о жалобах своего магазина («📋 ЗАДАЧА» с кнопками). Ежедневный обход: бот ведёт по всем тестерам магазина, кнопки «ОК / Заменён / Проблема / Пропустить», в конце сводка. Жалобы: «Взять в работу» → «Решено» (с описанием, что сделано). |
| **Админ** | Жалобы не получает — только наблюдатель: смотрит жалобы по магазинам (📥 Жалобы) и ответственных (карточка магазина → 👥 Сотрудники). Управляет: магазины, тестеры, сотрудники, админы, инвайт-коды, QR-коды, статистика. Если в магазине нет ни одного сотрудника, жалоба страховочно доставляется админам с пометкой. |

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\python -m pip install -r requirements.txt
# Linux/macOS:
.venv/bin/pip install -r requirements.txt

cp .env.example .env   # Windows: copy .env.example .env
# ... заполните .env (см. ниже)

python bot.py
```

### .env

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather): `/newbot` → имя → username. |
| `ADMIN_IDS` | Telegram ID админов через запятую. Свой ID: [@userinfobot](https://t.me/userinfobot). |
| `DB_PATH` | Файл SQLite (по умолчанию `letual.db`). |
| `REMINDER_TIME` | Время ежедневного напоминания про обход, `ЧЧ:ММ` местного времени сервера. |

## Раскатка на пилот (3 магазина)

1. **Создайте бота** у @BotFather, токен — в `.env`, свой ID — в `ADMIN_IDS`.
2. **Демо-данные** (по желанию): `python seed_demo.py` — 3 магазина по 10 тестеров.
3. Запустите `python bot.py`, откройте бота админом → `/admin` → **Магазины** → создайте
   свои магазины (или оставьте демо).
4. **Тестеры**: в карточке магазина — «Добавить тестер» по одному или «Импорт тестеров
   списком» (формат: `Бренд;Продукт;Место` по строке).
5. **QR-коды**: «QR-коды магазина» → бот пришлёт ZIP с PNG и печатный HTML-лист.
   Откройте HTML в браузере, распечатайте (Ctrl+P), вырежьте карточки и разместите
   рядом с тестерами. Пример макета: [demo_qr_preview.html](demo_qr_preview.html).
6. **Сотрудники**: `/admin` → Магазины → магазин → «👥 Сотрудники» → «➕ Добавить»:
   - **инвайт-кодом** — сгенерируйте код, передайте человеку ссылку + код (удобно на месте);
   - **пересылкой сообщения** — перешлите боту любое сообщение от человека, он определит автора
     сам (попросите человека сначала нажать /start у бота); если автор скрыт — пришлите его
     Telegram ID цифрами (@userinfobot).
   Увольнение/перевод: там же в списке «🚫 Убрать» у каждого сотрудника (перевод в другой
   магазин — просто добавьте его в новый, привязка перезапишется).
7. **Админы**: `/admin` → «👑 Админы» → добавить пересылкой сообщения или по ID, снять —
   кнопкой «🚫». Админы из `ADMIN_IDS` (.env) помечены 🔒 и защищены от снятия — это
   страховка от потери управления. Снять себя с прав бот не даст.
8. Покупатели просто сканируют QR — никаких регистраций.

Готово: жалобы идут в нужный магазин, сотрудники делают обходы, статистика копится в `/admin`.

## Прокси (если api.telegram.org недоступен)

На части российских провайдеров Telegram API заблокирован — бот при старте падает с
`TelegramNetworkError: Cannot connect to host api.telegram.org:443`. Решение — указать
прокси в `.env`:

```env
PROXY_URL=socks5://127.0.0.1:10808
```

Поддерживаются `http://`, `socks4://`, `socks5://`, в т.ч. с авторизацией:
`socks5://user:pass@host:port`.

Где взять прокси:

- **Локальный VPN-клиент** (v2rayN, Clash, NekoBox и т.п.) обычно поднимает локальный
  прокси, когда включён. Типичные порты: v2rayN — `socks5://127.0.0.1:10808` или
  `http://127.0.0.1:10809`; Clash — `http://127.0.0.1:7890`. Порт смотрите в настройках
  клиента. ВАЖНО: бот должен работать, даже когда VPN-клиент выключен нельзя — если
  клиент закрыт, прокси недоступен и бот остановится.
- **VPN в режиме TUN / «системный VPN»** — весь трафик идёт через VPN, `PROXY_URL` не нужен.
- **Арендованный прокси** (http/socks5) — укажите его адрес в `PROXY_URL`.

Бот при старте сам проверяет связь с Telegram и при проблеме выведет понятную ошибку
с этой подсказкой вместо длинного трейсбека.

## Команды бота

- `/start` — главное меню (зависит от роли)
- `/staff` — вход сотрудника по инвайт-коду
- `/admin` — админ-панель
- QR-код → `https://t.me/<бот>?start=c-<КОДТЕСТЕРА>` — жалоба на конкретный тестер

## Тесты

Без Telegram, офлайн: `python smoke_test.py` — проверяет БД, жизненный цикл жалобы,
обходы, генерацию QR (PNG/ZIP/печатный HTML).

## Деплой

### Docker

```bash
docker build -t tester-bot .
docker run -d --name tester-bot --restart unless-stopped \
  -v $(pwd)/letual.db:/app/letual.db \
  -e BOT_TOKEN=... -e ADMIN_IDS=... tester-bot
```

### systemd (Linux)

```ini
[Unit]
Description=Tester bot
After=network.target

[Service]
WorkingDirectory=/opt/tester-bot
ExecStart=/opt/tester-bot/.venv/bin/python bot.py
Restart=always
EnvironmentFile=/opt/tester-bot/.env

[Install]
WantedBy=multi-user.target
```

## Структура проекта

```
bot.py               # точка входа (long polling)
config.py            # настройки из .env
db.py, schema.sql    # SQLite: подключение и схема
constants.py         # статусы и русские подписи
keyboards.py         # инлайн-клавиатуры
notifier.py          # уведомления сотрудникам/админам
scheduler.py         # ежедневное напоминание про обход
handlers/
  common.py          # /start, deep-link, жалоба покупателя, /staff
  employee.py        # обход, работа с жалобами
  admin.py           # панель: магазины, тестеры, инвайты, QR, статистика
services/
  users.py           # роли и инвайт-коды
  complaints.py      # жалобы
  checkups.py        # обходы
  qr.py              # QR PNG/ZIP + печатный HTML
seed_demo.py         # демо-данные (3 магазина)
smoke_test.py        # офлайн-тесты логики
```

## Данные

SQLite-файл (`letual.db`): магазины, тестеры, пользователи, жалобы, обходы, инвайт-коды.
Бэкап = копия файла. При росте пилота схема переносится на PostgreSQL без изменения
логики (aiosqlite → asyncpg).
